DOKUMENTASI SETUP PROJECT TRACER STUDY

- Tujuan Project: Project ini untuk membuat Sistem Informasi Tracer Study Alumni (SERU).
- Backend: Laravel digunakan sebagai backend framework.
- Frontend: Vue 3 digunakan sebagai frontend framework (menggantikan Blade).
- Bridge: Inertia.js digunakan sebagai bridge antara Laravel dan Vue, memungkinkan SPA (Single Page Application) tanpa perlu membuat API secara terpisah.
- Styling: Tailwind CSS digunakan untuk styling.
- Bundler: Vite digunakan untuk asset bundling dan development.
- Database: Database menggunakan MySQL/MariaDB.
- Local Environment: Local environment menggunakan Laragon.
- Lokasi Project: c:\ALL FILES\Tugas Akhir\tracer\tracer-study

CARA MENJALANKAN PROJECT
1. Buka dua terminal.
2. Di terminal pertama, jalankan backend Laravel: php artisan serve
3. Di terminal kedua, jalankan Vite development server: npm run dev
4. Akses http://localhost:8000 di browser.

FUNGSI FOLDER UTAMA LARAVEL
- app/: Berisi inti kode aplikasi seperti Controller, Model, dan Middleware.
- bootstrap/: Berisi script untuk inisialisasi aplikasi (contoh: app.php).
- config/: Berisi semua file konfigurasi aplikasi.
- database/: Berisi migration, seeder, dan factory untuk database.
- public/: Folder root untuk web server, berisi file entry index.php serta aset yang sudah dicompile.
- resources/: Berisi raw asset seperti view Blade (app.blade.php), CSS, dan file Javascript/Vue.
- routes/: Berisi definisi routing aplikasi (contoh: web.php).
- storage/: Berisi file yang digenerate oleh Laravel seperti log, cache, dan file upload.
- vendor/: Berisi dependensi Composer.

FUNGSI FOLDER resources/js
Folder ini merupakan pusat pengembangan frontend Vue dalam arsitektur Inertia.
- app.js: Entry point utama untuk inisialisasi Vue dan Inertia.
- Pages/: Berisi komponen Vue yang merepresentasikan halaman secara penuh (dirender oleh controller Laravel).
- Layouts/: (Opsional) Berisi komponen layout untuk membungkus halaman.
- Components/: (Opsional) Berisi reusable komponen Vue yang lebih kecil.

MANAJEMEN OTORISASI (ROLES)
- Terdapat 4 peran utama:
  1. `superadmin`: Otoritas tertinggi sistem, bertanggung jawab penuh atas konfigurasi sistem serta modul Kelola Kuesioner (manajemen butir pertanyaan F1-F22, alur jump logic, dan opsi jawaban).
  2. `admin_biro3`: Administrator Biro 3 (Kemahasiswaan, Alumni & Pengembangan Karir), bertanggung jawab atas Manajemen Data Alumni, Sinkronisasi Profil LinkedIn, dan Pemantauan Partisipasi Kuesioner.

- `CheckMustChangePassword` menahan user (khususnya alumni baru) agar mengganti password sebelum bisa masuk sistem.

ATURAN PENGEMBANGAN (CODING GUIDELINES)
1. **Update Log**: Setiap update atau fitur baru HARUS selalu dicatat ke dalam `UPDATE_LOG.md`.
2. **Komentar Kode**: Setiap perintah code, routes, functions, view, dan logika krusial HARUS memiliki comment penjelasan yang deskriptif di dalam kodenya.
3. **Penamaan Konsisten**: Nama file HARUS disesuaikan dengan fungsinya dengan jelas. Hal ini berlaku untuk nama Controller, nama routes, view, fungsi, variabel, dll.
4. **Pemisahan Tanggung Jawab (Separation of Concerns)**: Semuanya (business logic, query, security, manipulasi data berat) HARUS melalui Backend (Laravel). Frontend (Vue) difungsikan murni HANYA sebagai tampilan (UI/Presentation Layer) saja.

ARSITEKTUR KUESIONER (STEP 4 & 5)
1. Tabel Dinamis (Hierarkis):
   - `questionnaires` -> `question_sections` -> `questions` -> `question_options`
   - Jawaban disimpan di tabel `responses` dengan format kolom `answer_text` (untuk jawaban tunggal) dan `answer_json` (untuk checkbox / matriks).
2. Format Jump Logic (Google Forms Style):
   - Kolom `jump_to` di tabel `question_options` mencatat langsung kode pertanyaan tujuan jika opsi tersebut dipilih (misal: 'Saya tidak mencari kerja' -> jump_to: 'F8').
   - Sistem Vue di halaman kuesioner mendeteksi `jump_to` dari opsi jawaban yang dipilih dan melakukan skip/bypass pertanyaan dan section di antaranya secara dinamis.
   - Jump logic dapat dikelola dengan mudah oleh admin melalui panel Admin Biro Tiga (Kelola Pertanyaan).
3. Manajemen Tipe Data Input:
   - Komponen UI dipetakan murni berdasarkan atribut `type` dari DB: `text`, `number`, `radio`, `checkbox`, `radio_input` (dengan inputan ekstra), `multiple_number`, `matrix`, `matrix_dual`.
4. Scoping Pertanyaan Program Studi:
   - Kolom `prodi_id` di tabel `questions` (nullable foreign key ke `prodis.id`).
   - Jika bernilai NULL, pertanyaan berlaku umum untuk semua program studi.
   - Jika diisi, pertanyaan hanya disajikan untuk alumni prodi terkait (disaring otomatis di `KuesionerController` tanpa hardcode di Vue, misal: F2E untuk prodi Filsafat Keilahian kode 31).
   - Admin Biro 3 dapat memilih target program studi dan memantau statusnya via badge prodi di panel Kelola Pertanyaan.
5. Khusus Evaluasi Kompetensi (F17 / Komparasi Dual Berdampingan):
   - Pasangan pertanyaan berdampingan: Pertanyaan ganjil = Kolom A (Kemampuan Diri Anda / Tingkat Penguasaan), Pertanyaan genap = Kolom B (Kontribusi Perguruan Tinggi).
   - Tampilan menggunakan tabel komparatif dengan sticky header, tema warna kontras (Hijau Emerald untuk Diri vs Biru Royal untuk Kampus), serta indikator komparasi dinamis (Diri > Kampus, Selaras, Kampus > Diri) pada kolom tengah.

ARSITEKTUR & STANDARISASI PENYIMPANAN RESPONSES (STEP 7)
1. Struktur Tabel `responses`:
   - `id`: Primary Key (BigInt Unsigned).
   - `alumni_id`: Foreign Key ke `alumnis.id`.
   - `question_id`: Foreign Key ke `questions.id`.
   - `answer_text`: Kolom Text/Varchar untuk representasi teks manusia, format angka tunggal, dan data siap ekspor.
   - `answer_json`: Kolom JSON untuk representasi array asli (multiple choice), rincian nominal (F13), dan input terstruktur (radio_input).
   - `created_at` & `updated_at`: Timestamp.

2. Strategi Penyimpanan Berdasarkan Tipe Pertanyaan (Dual Hybrid Storage):
   - **Teks / String Tunggal** (`text`, `searchable_select`):
     - `answer_text`: String teks murni (contoh: "Jl. Kaliurang Km 12").
     - `answer_json`: NULL.
   - **Angka Numerik Tunggal** (`number`, skala rating `single_choice` 1-5 pada F17):
     - `answer_text`: Angka murni (contoh: "5" pada F6, "2" pada F7, "4" pada F17).
     - `answer_json`: NULL.
     - *Manfaat*: Memungkinkan fungsi agregasi SQL langsung (`AVG()`, `SUM()`) dan terformat otomatis sebagai number di Excel.
   - **Pilihan Tunggal / Radio** (`single_choice`, `radio`):
     - Jika memilih opsi reguler: `answer_text` = opsi yang dipilih (contoh: "Ya", "Swasta"), `answer_json` = NULL.
     - Jika memilih opsi "Lainnya" + teks kustom: `answer_text` = "Lainnya: [isi_teks_alumni]" (contoh: "Lainnya: Merintis usaha"), `answer_json` = NULL.
   - **Pilihan Ganda / Checkbox** (`multiple_choice`, `checkbox`):
     - `answer_json`: Array JSON murni (contoh: `["Melamar ke perusahaan", "Mencari di internet", "Lainnya: Job Fair"]`). Menjaga keutuhan array tanpa takut terpecah oleh tanda koma teks.
     - `answer_text`: String gabungan dipisahkan koma (contoh: "Melamar ke perusahaan, Mencari di internet, Lainnya: Job Fair"). Siap diekspor langsung ke spreadsheet.
   - **Radio Input Kombinasi** (`radio_input`, seperti F3 dan F5):
     - `answer_json`: Object terstruktur `{"selected": "Kira-kira ... bulan sebelum lulus", "input": "4"}`.
     - `answer_text`: Kalimat utuh yang menggantikan titik-titik (contoh: "Kira-kira 4 bulan sebelum lulus").
   - **Rincian Angka / Pendapatan** (`multiple_number`, seperti F13):
     - Format Pengisian: Satuan ribuan rupiah dengan visual suffix `.000` otomatis (contoh: ketik 5000 untuk Rp 5.000.000, 750 untuk Rp 750.000). Dilengkapi peringatan pintar jika nominal diinput dalam jutaan penuh (>= 1.000.000) untuk mencegah kesalahan perkalian ganda.
     - `answer_json`: Object key-value numerik dalam rupiah penuh serta nilai total akumulasi `{"F13-01": 6500000, "F13-02": 750000, "F13-03": 0, "total": 7250000}`.
     - `answer_text`: Kalimat terformat rapi dengan label, rupiah, dan total akumulasi (contoh: "Dari Pekerjaan Utama: Rp 6.500.000, Dari Lembur dan Tips: Rp 750.000, Dari Pekerjaan Lainnya: Rp 0, Total Pendapatan: Rp 7.250.000").
     - Total Salary: Terkalkulasi secara reaktif dan otomatis disinkronisasi/diperbarui di database setiap kali alumni mengubah rincian pendapatan.

3. Integrasi & Sinkronisasi Profil Alumni (F1 s/d F2H):
   - Instrumen profil (F1, F2A, F2B, F2C, F2D, F2D1, F2E, F2E1, F2E2, F2E3, F2F, F2G, F2H) ditarik otomatis dari `data_akademiks`, `alumnis`, `companies`, dan `atasans` melalui `QuestionMapping`.
   - `KuesionerSyncService::syncProfileResponses($alumni)` otomatis mengisi tabel `responses` untuk setiap alumni saat:
     a. Database seeder dijalankan (`QuestionMappingSeeder`).
     b. Kuesioner dibuka oleh alumni (`KuesionerController`).
     c. Alumni mengubah/memperbarui profil diri di `/alumni/profil` (`SimpanProfilController`).
     d. Alumni menyimpan kuesioner (`SimpanJawabanController`).
   - Tabel `responses` terjamin 100% lengkap memiliki data untuk seluruh 23 instrumen tracer study.

4. Panduan Ekspor Data (Excel / CSV):
   - **Ekspor Cepat Laporan Manusia**: Cukup SELECT `answer_text`. Kolom di Excel langsung rapi, terbaca manusia, dan tidak ada tanda kurung siku `[]` atau petik `""`.
   - **Ekspor Statistik Resmi Dikti**: Gunakan `answer_json` untuk memetakan centang opsi ke kolom biner 1/0 dan angka numerik gaji ke kolom nominal terpisah.

STANDAR DOKUMENTASI KODE & ALUR HUBUNGAN BACKEND-INERTIA-FRONTEND (STEP 9)
1. Alur Penghubung (Lifecycle):
   - Browser akses URL -> Ditangkap di `routes/web.php` -> Memanggil Controller (Backend).
   - Controller melakukan query ke Database (Eloquent Model) -> Membungkus data -> Mengirim via `Inertia::render('Path/Komponen', ['props' => $data])`.
   - Inertia bertindak sebagai bridge (kurir JSON otomatis tanpa perlu membuat REST API manual).
   - Komponen Halaman Vue (`resources/js/Pages/...`) menangkap data via `defineProps` dan menampilkannya di template secara reaktif.

2. Hubungan Komponen Induk (Parent) dan Komponen Anak (Child):
   - Contoh pada Modul Profil Alumni:
     - `Index.vue` adalah Parent Component yang menerima `formData` dari `ProfilController.php`.
     - `Index.vue` membungkus data tersebut ke dalam `const form = useForm(props.formData)`.
     - Komponen anak (`FormAkademik.vue`, `FormPribadi.vue`, `FormOrangTua.vue`, `FormKarier.vue`) menerima variabel form tersebut melalui props operan: `<FormAkademik :form="form" />`.
     - Ketika tombol simpan di `Index.vue` ditekan, seluruh data dari keempat form anak dikirim serentak melalui `form.post('/alumni/profile')` ke `SimpanProfilController.php`.

3. Standar Komentar Kode:
   - Setiap Controller wajib mencantumkan komentar per-variabel untuk menjelaskan sumber data, tabel database yang digunakan, dan tujuan props yang dikirim ke Inertia.
   - Setiap Komponen Vue wajib mencantumkan komentar di bagian script yang merinci asal-usul props dan controller tujuan untuk setiap aksi (submit/logout).

4. Kuesioner Khusus (F13 & F17):
   - F13 (multiple_number): Input gaji format ribuan (suffix .000), total salary dihitung reaktif dan tersimpan otomatis di database (`answer_json.total` & `answer_text`).
   - F17 (komparasi berdampingan): Perbandingan Kolom A (Kemampuan Diri Saat Lulus) vs Kolom B (Kontribusi Kampus UKDW) dengan tabel rapi, skala 1 s/d 5, dan indikator komparasi minimalis tanpa overlap/clipping.
